## Findings

### Blocking

None.

### Significant

**#1: Tiles and `asp-2026.json` land flat at app bundle root, not in a `tiles/` subdirectory**

- Where: `ios/WePark/WePark.xcodeproj/project.pbxproj` — `PBXFileSystemSynchronizedRootGroup` (line 13–18) is the file-management strategy; the `PBXResourcesBuildPhase.files` array is empty (lines 111–112).
- What: Xcode's folder-sync mode copies the *contents* of `Resources/` (and its subdirs) into the bundle, but flattens subfolder structure for top-level resources. Confirmed from the built `.app`: `WePark.app/asp-2026.json` exists flat; `WePark.app/tile_*.json` exist flat (1028 files); there is no `WePark.app/tiles/` subdirectory. `WePark.app/index.json` is also flat.
- Expected (per spec §4.2): `Resources/tiles/index.json` and `Resources/tiles/tile_*.json` — implying code might be written to assume a `tiles/` path within the bundle.
- Impact: W2's `TileLoader` must use `Bundle.main.url(forResource: "tile_0_3", withExtension: "json")` (which works) rather than constructing a path like `Bundle.main.bundlePath + "/tiles/tile_0_3.json"` (which will fail at runtime). `asp-2026.json` must be loaded as `Bundle.main.url(forResource: "asp-2026", withExtension: "json")`. No W2 code exists yet, so nothing is broken today — but this must be documented before W2 starts or it will produce a silent runtime failure.
- Owner: `@ios-engineer` — add a note to `TileLoader.swift` and `ASPSuspensionService.swift` stubs that `Bundle.main.url(forResource:withExtension:)` is the correct loading path, not a constructed subpath.

**#2: Spec §4.4 says "41 dates" in two places; actual data has 42**

- Where: `docs/ios-mvp-spec.md` lines 326 and 342 (PR-branch version).
- What: Both instances say "41 dates" (`ASP_SUSPENSIONS_2026`, 41 dates` and `The 41 dates are listed in full`). The actual `index.html` has 42 entries; `asp-2026.json` has 42 entries; the Python verification confirms exact match at 42. This PR does not update those two spec sentences.
- Expected: Spec should say "42 dates" to match the data and avoid confusing future engineers who audit the JSON count against the spec.
- Owner: `@ios-engineer` or Tech Lead — one-line fix in `docs/ios-mvp-spec.md`.

**#3: `HANDOFF.md` line 83 says "41 dates from official NYC DOT PDF" — stale**

- Where: `HANDOFF.md` line 83.
- What: Same stale count. Not touched in this PR. Low operational impact (it's documentation), but contributes to future audit confusion alongside Finding #2.
- Owner: Tech Lead — one-line fix in `HANDOFF.md`.

### Minor / nit

**#4: iPad orientation keys present in pbxproj despite iPhone-only target family**

- Where: `project.pbxproj` lines 261 and 295: `INFOPLIST_KEY_UISupportedInterfaceOrientations_iPad = "UIInterfaceOrientationPortrait ..."`.
- What: These keys are Xcode's default scaffold output. With `TARGETED_DEVICE_FAMILY = 1` (iPhone only), they are inert — App Store Connect will ignore them for an iPhone-only build. Not a rejection risk. But they add noise and could mislead a future engineer into thinking iPad is planned sooner than §2.2 says.
- Owner: `@ios-engineer` — can delete both `INFOPLIST_KEY_UISupportedInterfaceOrientations_iPad` lines in a future cleanup commit. Not urgent.

**#5: `Views/.gitkeep` and `Models/.gitkeep` will be excluded at build time but still appear in git history as committed empty-folder anchors**

- Where: `ios/WePark/WePark/Models/.gitkeep`, `ios/WePark/WePark/Views/.gitkeep`.
- What: `EXCLUDED_SOURCE_FILE_NAMES = ".gitkeep"` (pbxproj lines 255 and 289) correctly prevents them from being compiled. They will not appear in the bundle. The pattern is intentional and works. Minor nit: once `Models/` and `Views/` have real Swift files added in W2, the `.gitkeep` files should be deleted so they don't generate "excluded" build log noise indefinitely.
- Owner: `@ios-engineer` — delete `.gitkeep` files when the first real Swift file lands in each folder.
