## Fix verified — Finding #1: RESOLVED

- `endDrivePillTopPadding` changed from `bannerState == .aspInEffect ? 0 : 44` to `paddingForBannerState(bannerState)`.
- New file-level pure function `paddingForBannerState(_ state: SuspensionBannerState) -> CGFloat` returns `44` for all three cases (`.aspInEffect`, `.todaySuspended`, `.tomorrowSuspended`) via an exhaustive `switch` with no `default` — the compiler confirms `SuspensionBannerState` has exactly these three cases, all banner-visible. There is no "no banner" case; the ASP banner is rendered unconditionally via `.safeAreaInset(edge: .top) { ASPBanner(state: bannerState) }`, so the pill always needs clearance. The fix is complete.
- Doc-comment corrected from the inverted "Zero when the banner is not showing (.aspInEffect)" to "Always non-zero: all three SuspensionBannerState cases render a visible banner."

## The 44-vs-100 magnitude question (raised pre-QA, resolved)

The reverted #31 used `100pt`; this fix uses `44pt`. Investigation: the two values live in different safe-area contexts.
- `recenterButtonStack` (top-right toolbar) uses `.padding(.top, 100)` — its comment states it manually clears "the ~44pt status bar and the ~40pt ASP banner." It sits in a context that does not get auto-pushed below the banner.
- The End Drive pill (`driveModeOverlayLayer`) respects the safe area, so the `.safeAreaInset(edge: .top)` banner already pushes it below the banner; the 44pt is additional clearance below that already-cleared position.
- **Empirically confirmed**: Kevin's manual smoke (Drive Mode active, 2026-05-28) shows the End Drive pill sitting cleanly below the red "ASP Suspended — Idul-Adha" banner. Since all three banner states return the same 44pt and the banners are the same height (~44pt), `.aspInEffect` clears identically. Not a bug.
