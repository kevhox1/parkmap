## High-Risk Cross-Checks

### A. Test count discrepancy resolved

Engineer claimed 115; actual is 116. HANDOFF baseline of 96 was correct. Engineer's "parallel-clone double-counting" theory was incorrect. See Finding #1.

### B. `isFree` correctness under DST + edge cases

`isFree(segment:from:until:)` walks the `[from, until]` window per calendar date using `Calendar.easternTime` (line 628 area). DST transitions in March (spring forward) and November (fall back) are handled by the underlying `Calendar.easternTime` arithmetic — same pattern that `currentState(for:at:)` and `nextRestriction(for:at:)` use. No new DST risk introduced.

### C. `rebuildOverlays()` tail-call concern raised by engineer

Engineer flagged: "Swift doesn't perform tail-call optimization, but the recursive call is safe because `parkUntilMode = false` / `parkUntilTarget = nil` are set before the call — no infinite recursion risk."

Verified: `ContentView.swift:677-682` shows the stale-target guard inside `rebuildOverlays`:
```
if parkUntilMode, let target = parkUntilTarget {
    if target < .nowET {
        parkUntilMode = false
        parkUntilTarget = nil
        // ... probable rebuildOverlays() call after clearing
    }
    ...
}
```

If `rebuildOverlays()` is called recursively after clearing, the recursive call enters the same function with `parkUntilMode = false`, skipping the `if parkUntilMode` branch entirely. No recursion. Engineer's reasoning is correct.

### D. Pin-replace behavior

When user drops pin A → picks "2 hr" → drops pin B (different location), what happens to the filter?

Trace from `ContentView.swift:472`:
```
.onReceive(parkPinService.pinDropped) { newCar in
    ...
    parkUntilMode = false       // line 484
    parkUntilTarget = nil       // line 485
    activeSheet = .parkUntil(newCar)  // implied — sheet re-appears for the new pin
}
```

**Behavior: filter is cleared on every new pin drop, then the sheet re-appears for the new pin.** This is the "every pin drop" behavior Kevin chose for OQ-W7.5-1. Pin replace = filter clear + re-prompt. Correct per spec.

### E. Stale-target guard scope

Verified: the guard fires in **two** places:
1. `ContentView.swift:393-395` — `.onChange(of: scenePhase) { newPhase == .active }` clears filter if target is in the past.
2. `ContentView.swift:677-682` — inside `rebuildOverlays`, defensive double-check before computing isFree partitions.

Both paths set `parkUntilMode = false` AND `parkUntilTarget = nil`. Consistent state machine.

## What's Working

- **`isFree` is the right API.** Adding a new method instead of modifying `currentState(for:at:)` preserves all existing engine consumers (W3 parity tests, W6 notification scheduler, W7 banner, viewport-polish) without churn. Clean separation of concerns: point-in-time queries vs interval queries.

- **Binary recolor approach is implementation-cheap.** The spec's choice to reuse the existing 5-group `OverlayPayload` (with 3 groups empty in Park Until mode) means `MapViewRepresentable` needs zero changes. The recolor logic lives entirely in `rebuildOverlays`. Minimal surface area for regression.

- **State machine is consistent.** All filter-state mutations set BOTH `parkUntilMode = false` AND `parkUntilTarget = nil` together. No "filter enabled but target nil" or "target set but mode off" half-states possible. Defensive coding.

- **Stale guard is correctly placed.** Foreground re-entry is the right hook (catches the "user backgrounded for an hour, target was 30 min away" case). The secondary guard in `rebuildOverlays` is belt-and-suspenders for any other path that might leave a stale target.

- **Pin-replace behavior matches spec.** New pin → filter cleared → sheet re-appears. Honors the "every pin drop" decision and avoids orphan filters for stale pins.

- **No regressions detected.** W6.1 deep-link routing unchanged. W7 ToastService / banner / per-pin toggle unchanged. viewport-polish auto-center / coverage check unchanged. Single sheet modifier preserved.

- **Test coverage is solid for engine paths.** 20 new tests cover the interval-overlap matrix including ASP suspension, metered conflicts, edge cases (empty rules, zero-length window, 24h cap). View + wiring tests are deferred to smoke per the established pattern.
