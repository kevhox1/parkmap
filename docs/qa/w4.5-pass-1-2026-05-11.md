**#1: Two stale "24h" references in `docs/design/ios-mvp-palette.md` create an internally inconsistent spec**

- Where: `docs/design/ios-mvp-palette.md` line 12 (§1 Design Premise) and line 33 (§2.1 table, row 4/green)
- What (line 12): Intro prose says "orange Wednesday evening (restriction coming in <24h), green for the two days in between." Under the new 6h threshold, Wednesday evening (~15h before Thu 7am ASP) is green, not orange. The example now describes the opposite of the actual behavior.
- What (line 33): The §2.1 table's green row says "ASP block whose next active window is **>24h away**" in the Triggered-by column, while the code uses ">6h" and the orange row above it was correctly updated to "within ~6 hours." A reader sees orange at <6h but green at >24h, implying a 6–24h no-man's-land where neither row applies.
- Expected: Line 12 should read "orange Thursday around 1am (within 6h of next ASP)"; line 33 should say ">6h away."
- Impact: No code impact. App behavior is correct. Spec readers — including future `@ios-engineer` and `@designer` sessions — will get wrong expectations and may write new tests or features against the stale 24h values.
- Owner: `@ios-engineer` (doc fix, same PR or fast follow)
