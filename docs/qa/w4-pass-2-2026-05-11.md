## Findings

### Significant

**#1 (pass-1 finding #1 — not fully resolved): Close button precedes safety label in VoiceOver focus order**
- Where: `ios/WePark/WePark/Views/BlockDetailView.swift:73–117` — `headerRow` (containing the ✕ button at lines 93–103) appears before `safetyLabelView` in the `VStack` source order
- What: The engineer hid the title and subtitle `Text` elements with `.accessibilityHidden(true)`. This was option (c) from pass-1 finding #1. However, the ✕ close button within `headerRow` is NOT hidden and remains focusable. VoiceOver navigates left-to-right within an HStack: in `headerRow`, the title VStack (now all-hidden) comes first, then `Spacer()`, then the ✕ button. After the HStack, VoiceOver moves to `safetyLabelView`. Net VoiceOver order in the sheet: **✕ close button → safety label → rule rows → park-here stub**. The safety label is the second focusable element, not the first.
- Expected per spec §3.5 / palette §5.1 point 2: "This must be the first focusable accessibility element in the sheet."
- Engineer's comment at `BlockDetailView.swift:77-80` incorrectly claims the hiding achieves this — it does not, because the ✕ button was not also hidden or reordered.
- Repro: Enable VoiceOver, tap any polyline to open the sheet, swipe right from the color band. First announced: "Close block details, button" (the ✕). Second: the safety label text.
- Fix options: (a) Add `.accessibilitySortPriority(1)` to `safetyLabelView` and lower/remove priority from the close button (this reorders VoiceOver focus without changing visual layout or removing the close button from VoiceOver); (b) Move the ✕ button after the safety label in source order (wrap in overlay or ZStack) so visual layout is preserved but VoiceOver order changes; (c) Add `.accessibilityHidden(true)` to the close button (removes it from VoiceOver entirely — NOT recommended, as the close button should be reachable by VoiceOver users).
- Recommendation: Option (a) — `.accessibilitySortPriority(1)` on `safetyLabelView` and `.accessibilitySortPriority(0)` on the close button. This is the minimal targeted fix.
- Owner: `@ios-engineer`

## What's working

**Architecture refactor is the right call and is correctly implemented.** The 6-overlay `MKMultiPolyline` model reduces Metal resource usage from 1.22M to 6 resource groups — a 200,000x reduction. The decision doc's analysis was accurate and the implementation matches it precisely. The visual result (5 severity colors, selected-block highlight, dynamic 60s recompute, zoom-threshold gating) is identical to the original W3/W4 design intent. No product regression.

**Z-order fix is correct and observable.** Green (freeComfortably) is last-added and therefore topmost at intersection corners. The "mostly red on Monday afternoon" symptom Kevin observed was a real Z-order bug; the fix is real and correctly implemented.

**`regionDidChangeAnimated` `DispatchQueue.main.async` fix is sound.** The `[weak self]` capture is correct. The feedback loop analysis shows the threshold guard in `updateUIView` breaks any potential region-write cycle. The fix eliminates the "Modifying state during view update" SwiftUI warning without introducing new races.

**HP-13 test documents a genuine correctness story.** The test correctly proves the engine finds Thursday (not the following Monday) when Thursday is not suspended, and separately confirms that the "Free until Monday" label Kevin saw on May 11 was correct engine behavior (Thursday May 14 is the Ascension, suspended). The test uses a real past date (May 4) with a known non-suspended Thursday (May 7), making it a stable regression test.

**LRU cache at 200 tiles is the right balance.** At ~25 KB decoded/tile, 200 tiles = ~5 MB of segment data in the LRU. The previous cap of 50 was too small for a Manhattan panning session (user can cross more than 50 tile boundaries), causing the "only upper Manhattan renders" symptom. 200 = ~25% of all 1,028 tiles; caching all 1,028 would be fine too but 200 is conservatively correct.

**Test suite: 44 passed, 0 failed.** Independently verified by QA on the booted simulator. This closes AC-W4.10 definitively (pass-1 was unable to run tests due to swap pressure; that blocker is now resolved).

**`dismissSheet()` is now a clean single-responsibility function.** Only sets `isSheetPresented = false`. Segment reference stays live during the animation. Pass-1 finding #2 is fully resolved.
