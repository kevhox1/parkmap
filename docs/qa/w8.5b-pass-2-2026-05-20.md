**Pass-1 status**: Significant finding

A code comment at the insertion site reads "S-1 fix (PR #29 QA pass-1 S-1)" and explains the invariant. The change is fully localized — no unrelated edits in the diff.

The visibility promotions (`private` to `internal` for `OverlayTag`, `TaggedMultiPolyline`, `RoutePolyline`) are the minimum required to allow `@testable import WePark` to type-check overlays. Each promotion is annotated with a doc comment stating it is an implementation detail, not public API.

### M-1 — MKLocalSearch.start timeout

**Pass-1 status**: Minor finding
**Pass-2 status**: RESOLVED

Commit `695a8c5` rewrites `selectCompletion` in `DriveModeDestinationView.swift`. The callback-based `search.start { response, error in ... }` is replaced with a `Task { @MainActor in }` that races the async `search.start()` overload against a `Task.sleep(for: .seconds(timeoutSeconds))` inside `withThrowingTaskGroup`. The timeout parameter defaults to `10` and is overridable for tests. When the timeout child wins, it throws `_SearchTimeoutError`; the `catch is _SearchTimeoutError` branch sets `isResolvingAddress = false` and `errorMessage = "Search timed out. Try again."` and clears `resolvedCoordinate`/`resolvedName`. When search succeeds first, `group.cancelAll()` is called before returning the `MKMapItem`, cleanly cancelling the timeout task — no zombie state. The existing error path (`Couldn't resolve address...`) is unchanged.

`SearchTimeoutError` is declared `internal` at file scope; `_SearchTimeoutError` is a `typealias` for it (used inside the view's catch clause). This is slightly unusual but functionally identical — both names resolve to the same type so `catch is _SearchTimeoutError` and `catch is SearchTimeoutError` are equivalent.

The new test `testResolveAddress_searchTimeout_setsErrorAndClearsResolvingState` (commit `40e0775`) exercises the state machine directly with a 1-nanosecond timeout racing a 60-second "search" sleep. The test asserts `isResolvingAddress == false`, `errorMessage == "Search timed out. Try again."`, `resolvedCoordinate == nil`, and `resolvedName == nil`. It is network-free and ran in 0.004s. It would fail without the M-1 fix because, in the original implementation, `SearchTimeoutError` did not exist and no state transitions occurred on timeout.
